# Spring Boot + Karaf OSGi Dual-Deployment Example

This project demonstrates how to create a Spring Boot web application with JDBC/JNDI that can run in multiple environments with **minimal effort**:

1. **Standalone** - Spring Boot with embedded Tomcat
2. **Docker** - Containerized deployment
3. **Apache Karaf OSGi** - As a Web Application Bundle (WAB)

## Architecture Overview

The key architectural decisions that enable multi-environment deployment:

### 1. WAR Packaging (Not JAR)
```xml
<packaging>war</packaging>
```
- WAR can run standalone with embedded Tomcat
- WAR deploys to Karaf as a Web Application Bundle (WAB)
- Standard servlet container abstraction works in both environments

### 2. SpringBootServletInitializer
```java
public class DemoApplication extends SpringBootServletInitializer {
    @Override
    protected SpringApplicationBuilder configure(SpringApplicationBuilder application) {
        return application.sources(DemoApplication.class);
    }
}
```
- Enables deployment in external servlet containers (Karaf's PAX Web)
- Maintains standalone execution via `main()` method

### 3. Environment-Aware DataSource Configuration
```java
@Bean
public DataSource dataSource() {
    // Try JNDI lookup first
    DataSource jndi = lookupJndiDataSource();
    if (jndi != null) return jndi;

    // Fallback to direct connection
    return createDirectDataSource();
}
```
- Automatically detects runtime environment
- Uses JNDI in OSGi, direct connection standalone
- OSGi service registry lookup as fallback

### 4. OSGi-Compatible MANIFEST.MF
Generated by Apache Felix maven-bundle-plugin:
```xml
<Web-ContextPath>/spring-jdbc-app</Web-ContextPath>
<Import-Package>
    javax.servlet.*;version="[3.1,6)",
    javax.sql,
    org.osgi.framework;version="[1.8,2)",
    *;resolution:=optional
</Import-Package>
```

## Quick Start

### Prerequisites
- Java 17+
- Maven 3.6+ or use the included wrapper
- Docker (optional)
- Apache Karaf 4.4.x (for OSGi deployment)

### Build the Application
```bash
./mvnw clean package
```

This creates: `target/spring-boot-karaf-jdbc-1.0.0-SNAPSHOT.war`

## Deployment Scenarios

### Scenario 1: Standalone (Embedded Tomcat)

```bash
# Build and run
./mvnw clean package
java -jar target/spring-boot-karaf-jdbc-1.0.0-SNAPSHOT.war

# Or use Spring Boot plugin
./mvnw spring-boot:run
```

**Access:**
- Application: http://localhost:8080/spring-jdbc-app/api/products
- H2 Console: http://localhost:8080/spring-jdbc-app/h2-console
- Health: http://localhost:8080/spring-jdbc-app/api/products/health
- Info: http://localhost:8080/spring-jdbc-app/api/info

**Configuration:**
Uses H2 in-memory database by default. Configure in `application.yml`.

### Scenario 2: Docker Deployment

#### Option A: Docker Compose (Recommended)
```bash
# Start application with PostgreSQL
docker-compose up -d

# With PgAdmin (optional)
docker-compose --profile tools up -d
```

**Access:**
- Application: http://localhost:8080/spring-jdbc-app/api/products
- PgAdmin: http://localhost:5050 (admin@example.com / admin)

```bash
# Build OCI image using Spring Boot's buildpack support
```

```bash

docker run -p 8080:8080 \
  -e SPRING_PROFILES_ACTIVE=docker \
  -e DB_HOST=host.docker.internal \
  spring-boot-karaf-jdbc:latest
```

### Scenario 3: Apache Karaf OSGi Deployment

This is the key scenario - deploying the same application to Karaf OSGi container.

#### Step 1: Prepare Karaf

```bash
# Start Karaf
$KARAF_HOME/bin/karaf

# Install required features
karaf@root()> feature:install http http-whiteboard war jdbc jndi transaction
karaf@root()> feature:install pax-web-http-jetty
```

#### Step 2: Install Database Driver

```bash
# For H2
karaf@root()> bundle:install -s mvn:com.h2database/h2/2.2.224

# For PostgreSQL (production)
karaf@root()> bundle:install -s mvn:org.postgresql/postgresql/42.7.1
```

#### Step 3: Configure DataSource

Copy the appropriate datasource configuration to Karaf:

```bash
# Copy H2 config (for development)
cp karaf/datasource-h2.cfg $KARAF_HOME/etc/org.ops4j.datasource-AppDataSource.cfg

# Or copy PostgreSQL config (for production)
cp karaf/datasource-postgres.cfg $KARAF_HOME/etc/org.ops4j.datasource-AppDataSource.cfg
```

Verify DataSource is registered:
```bash
karaf@root()> jdbc:ds-list
Name          | Product    | Version
AppDataSource | H2         | 2.2.224
```

#### Step 4: Deploy the WAR

```bash
# Install WAR as Web Application Bundle
karaf@root()> bundle:install -s webbundle:file:///path/to/target/spring-boot-karaf-jdbc-1.0.0-SNAPSHOT.war?Web-ContextPath=/spring-jdbc-app

# Verify deployment
karaf@root()> bundle:list | grep spring
karaf@root()> web:list
```

#### Step 5: Access via Karaf's Integrated Proxy

**Default URL:** http://localhost:8181/spring-jdbc-app/api/products

Karaf's PAX Web uses Jetty on port **8181** by default.

#### Proxy Configuration

Edit `$KARAF_HOME/etc/org.ops4j.pax.web.cfg`:

```properties
# HTTP port
org.osgi.service.http.port = 8181

# HTTPS port (optional)
org.osgi.service.http.port.secure = 8443

# Context session timeout
org.osgi.service.http.session.timeout = 30

# HTTP connector max threads
org.ops4j.pax.web.server.maxThreads = 150
```

#### Using Karaf Feature Descriptor

Alternatively, use the provided feature descriptor:

```bash
# Add feature repository
karaf@root()> feature:repo-add mvn:com.example/spring-boot-karaf-jdbc/1.0.0-SNAPSHOT/xml/features

# Install the feature (includes all dependencies)
karaf@root()> feature:install spring-boot-karaf-jdbc
```

## How It Works in Karaf

### Web Application Bundle (WAB)

When deployed to Karaf, the WAR becomes a WAB (Web Application Bundle):

1. **PAX Web** provides the servlet container (Jetty)
2. **OSGi MANIFEST.MF** declares bundle metadata and imports
3. **JNDI Service** provides DataSource lookup
4. **HTTP Service** exposes the web application

### DataSource Resolution

The application's `DataSourceConfig` attempts these lookups in order:

1. Standard JNDI: `java:comp/env/jdbc/AppDataSource`
2. OSGi service: `osgi:service/javax.sql.DataSource`
3. Direct OSGi service registry lookup
4. Fallback to direct HikariCP connection

### Karaf Proxy Integration

Karaf's integrated proxy (PAX Web) handles:
- HTTP/HTTPS termination
- Request routing to WAB
- Session management
- Security (if configured)

Configure proxy settings in `org.ops4j.pax.web.cfg`:

```properties
# Enable virtual hosts
org.ops4j.pax.web.virtual.hosts = localhost, myapp.example.com

# Configure connectors
org.osgi.service.http.port = 8181
```

## Troubleshooting

### Karaf Deployment Issues

```bash
# Diagnose bundle
karaf@root()> diag <bundle-id>

# Check bundle headers (verify OSGi manifest)
karaf@root()> bundle:headers <bundle-id>

# View logs
karaf@root()> log:tail

# Check web contexts
karaf@root()> web:context-list
```

### Common Problems

1. **Missing imports**: Check `Import-Package` in MANIFEST.MF
2. **ClassNotFoundException**: Bundle dependency not resolved
3. **DataSource not found**: Verify DataSource is registered with `jdbc:ds-list`
4. **Port conflict**: Change port in `org.ops4j.pax.web.cfg`

### Verify Environment Detection

```bash
# Check which environment the app detected
curl http://localhost:8181/spring-jdbc-app/api/info
```

Should return:
```json
{
  "detectedRuntime": "Apache Karaf OSGi",
  "osgiEnvironment": true,
  "osgiFramework": "Apache Software Foundation 1.10.0"
}
```

## Key Takeaways

1. **WAR packaging** is essential for Karaf deployment
2. **SpringBootServletInitializer** enables external container support
3. **Environment-aware configuration** detects runtime and adapts
4. **OSGi MANIFEST.MF** must declare proper imports (use maven-bundle-plugin)
5. **JNDI abstraction** provides consistent DataSource access
6. **Minimal code changes** - same codebase runs everywhere

The application automatically adapts to its runtime environment, making it truly portable between standalone, Docker, and Karaf OSGi deployments.

## Production Considerations

1. **Transaction Management**: Configure JTA for distributed transactions in Karaf
2. **Security**: Add Spring Security, integrate with Karaf's JAAS
3. **Monitoring**: Export JMX MBeans, integrate with Karaf's management
4. **Clustering**: Consider Karaf Cellar for clustered deployment
5. **Hot Deployment**: Karaf supports hot reloading of bundles
6. **Configuration**: Use Karaf's ConfigAdmin for dynamic configuration
